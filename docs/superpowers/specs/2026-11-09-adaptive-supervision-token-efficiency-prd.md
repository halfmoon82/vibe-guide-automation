## 1. 产品目标与来源

让简单任务不承担完整编排成本，让长期复杂任务保持可靠恢复；监工遇到 `blocked_unknown` 主动查证和推进，等待与重复返工不把监工、developer、reviewer 的宿主历史无限拉长。

本稿承接 [优化设计](2026-11-09-adaptive-supervision-token-efficiency-design.md) 与 [5.2.8 监工责任 PRD](2026-11-04-v528-supervisor-responsibility-prd.md)。不改后者的历史批准正文，不把本稿直接套用到其活跃 plan/run。

- 不安装/启动 Ollama、不下载模型、不修改 AGENTS、系统权限、凭据或代理；本轮只编写文档。

### 2.3 评估方法的问题

旧五维把步骤数、跨域、不确定性、失败代价、工具链相加，但它们不全意味着需要更多编排层级：风险可能要求更严验证，未知可能要求先调研，工具链可能只是一次安装授权；都不必然要求更多 worker。步骤数又容易随拆分口径变化，能被“拆成测试/文档/代码三项”虚增。

因此不把上一稿的 `>15 且 N≥5 且 P≥3 且 H>4小时` 固化成产品硬门。这组默认值保留为候选基线，新增方法需用历史回放和前瞻实测选择。

## 3. 新入口：三档不变，改进评估方法

### 3.1 先识别生命周期，再评估新任务

可靠绑定的继续/返工/心跳/接班进入当前执行档预检，不重评分、不重建计划。新目标或实质范围变化才重新评估。仅有短词“继续”而无可靠绑定不猜任务。

新任务的最小评估分两部分：

1. **难度/风险画像**：保留旧五维便于对照，用锚点与证据给区间，不装作精确；风险、权限、GUI 门和验收要求单独列出，不靠总分代替。
2. **编排收益事实**：是否需要持续委派、真正独立可验收的业务节点 N、扣除写冲突/依赖/授权容量后的有效并行 P、是否多波协调/跨会话恢复、是否需要持久跨节点验收/动作对账。

不要求每条任务都填满新表；已有事实足够就路由。N 不含独立 reviewer、机械测试步骤、文档收口或引擎自动追加的 integration-review。P 应区分计划可行值与已观测值；预计周期分“本会话可结束/需续接/跨天”，不把外部等待算有效工时。

### 3.2 候选决策树（推荐，待确认）

| 档位 | 核心判据 | 例子与约束 |
|---|---|---|
| A：轻执行 | 不需要持续的多任务委派/协调，原会话可可靠完成 | 简单工作、只读分析、需求设计；高分分析也不强拆 worker；有风险仍用相应测试/授权 |
| B：轻监工 | 有真实委派/独立审查收益，但小任务板足以管理状态、依赖与恢复 | 常见 1–4 业务节点；短周期或单个长串行 writer；可并行；少量续接不自动升级 C |
| C：完整 run | 持久跨节点协调、验收/副作用对账确有收益，且小任务板不足；典型是复杂多节点、多波/跨会话且有效并行高 | N≥5、P≥3、长周期是强提示而非必要且充分条件；四节点但有复杂恢复合同的合成边界场景，也可由当时真实需求支持选 C |

人工明确要求完整流程仍可选 C，路由不授予执行权限。B/C 边界由可观察管理需求解释，不能仅写“感觉复杂”。可引用的事实包括：多波硬依赖在中断后仍需重算 ready、上游验收撤销需阻断/重验下游、多个在途副作用需跨会话对账、跨节点共享批准需可追溯变更；引用当前确有需要的项目即可，不要求集齐另一份门禁清单。**单个危险命令不构成 C 的充分理由**。大量短、同构、无依赖任务可仍走 B 的有界批次，不为节点数多强行完整 PRD。

难度分只提供默认建议：旧≤8 常为 A、9–15 常为 B 候选、>15 检查 C 收益；不建立“总分一到就升级”的新版硬映射。保留评分展示，但输出应包含档位理由，例如：

```text
S1：14–16（画像）→轻监工；3 个业务节点、有效并行 2、单波，验收清楚。
S1：17–19（画像）→完整 run；4 个业务节点、跨会话恢复及共享验收对账。
```

范围/验收不明先澄清或做有界只读探查；不是先建复杂计划再发现产品未定。技术估计不明由 agent 查证，不把工程分诊表丢给产品经理。

### 3.3 历史回放与校准

- 比较三种候选：① 旧 8/15＋现有条件；② 上一稿 8/15＋5/3/4小时；③ 本稿画像＋收益决策树。不能只展示支持新方案的案例。
- 先用可交付的 H1–H4、H7 做历史种子；合成边界用例单列，不混入历史样本数。H5/H6/H8 未交付原材料，不进入回放/校准；后续经允许抽取更多样本，按同一根任务分组，修订稿和返工不当独立任务重复计数。
- 入口回放只用当时可见信息；事后故障作为结果评估，不泄露未来信息给入口。缺当时工期/分数保持 unknown，不凭结果倒填 20 分。
- 独立标注“最低足够档位/允许档位集合＋依据”，允许 A/B 或 B/C 都合理；争议单列，不强造唯一真值。旧实际选择不是黄金答案。正式评测才引入独立标注者，本轮未委派审阅。
- 同一项目/根任务按时间或项目分组留出测试集；不把同源修订同时放训练/验证。样本少时报告数量和区间，不声称通用准确率。
- 衡量错误升级、遗漏恢复能力、无谓提问、首轮输入、决策时延 P95、每验收节点总 token/时间与质量。风险/授权遗漏为单独否决项，不能用平均准确率掩盖。
- 有可靠概率输出和足够标注时才计算 ECE；模型自报“90%自信”不是经校准概率。少样本不承诺 ECE≤0.05。

既有 [整合 PRD](2026-10-13-supervisor-integrated-prd.md) §5.10/AC-E1 的分诊钩子/网关降级和 ECE 要求单独保留来源；新评测不冒充已满足该合同。若要替代其验收须明确修订，不能以本稿测试通过关闭旧 issue。

### 3.4 入口触发加固：不是把规则文字写得更重

**源码结论：已具备协议物化、规则提案和 CLI 内筛选，但不足以证明“每个宿主的每条请求必经 vibe-entry”。** 本次核对固定 v5.2.7 基线 `885236783e1a680d7165ee2ee2c4e0002430a30a`，不是把本地 v5.1.16 当最新版本：

| 现有证据 | 已做到 | 不能据此宣称 |
|---|---|---|
| `initializer.py:295/388`、`protocols/__init__.py` | 生成规则提案并物化技能；已知未编辑旧协议可按摘要刷新 | 提案已经采纳、宿主实际读了文件、每轮都触发 |
| `scanner.py:604` 的 `VIBE_ENTRY_RULES` | 要求 agent 会话内自评 S0/S1，简单请求不调 CLI | 公共逐请求 hook 已安装并执行 |
| `session_entry.py:268/293` | 被调用时可路由新任务/继续消息，无派发副作用 | 宿主所有请求都已调用它 |
| `cli.py:2776–2783` | 已初始化项目的 CLI 调用经过 `screen_session`，传入的是命令名等工程标识 | 未调用 CLI 的用户请求、普通文件编辑也被相同机制拦截 |
| `scanner.py:560`、`doctor.py:170` | Claude 规则入口/导入关系静态检查；检测部分旧入口冲突 | 真实当轮加载、执行顺序或其他 provider 逐轮覆盖已获验证 |
| `tests/test_vibe_entry_protocol.py`、`tests/test_entry_tightening.py` | 协议、物化及路由回归 | 真实 App 中新建、续接、心跳均已端到端触发 |

9 月入口 PRD 的非目标明确“不做平台 hook”；10 月整合 PRD 又提出分诊钩子和真实规则加载要求。检查上述源码及 adapters 未找到对应的通用逐请求 hook/Ollama 接线，属于本次源码覆盖缺口，不推断任何平台不具备这些公开能力。

**最小方案：一份路由内核＋宿主薄适配＋已有执行边界，不再建入口调度服务。**

1. **安装时接通**：针对实际 provider/版本探测公开的请求前 hook、规则导入、受控启动接口。展示变更并授权采纳入口块/注册；保留用户定制和已明确拒绝的块。不把“已提案”标成“已启用”。桌面 App、CLI 和不同 provider 分别记录验证，不互相代替。
2. **按请求触发，不只 session-start**：支持公开逐请求 hook 的宿主必须覆盖新会话首轮、后续新需求、恢复会话和原生任务委派；仅启动 hook 不足。hook 先本地识别项目和生命周期，只提供短入口提示/必要绑定；需语义判断时由当前主 agent 回合完成，不另起分诊模型。不要求每轮启动 CLI、调用 Ollama或重读完整技能。
3. **生命周期快路径**：已验证授权的心跳/接班/返工/worker 续接直达角色执行预检，不重跑 S1 或加载 PRD 协议；新目标仍评估。保护 UI 设计确认、授权、唯一 writer 等原有真实边界，但不为心跳新增产品门。
4. **能力如实分级**：有真实逐请求触发记录且受控动作可保护的称“已验证强触发”；只有规则导入/提示的称“规则引导”；尚无证据称“未验证”。宿主若只提供部分可拦截工具，注明覆盖范围。没有公开可用 hook 时继续规则路径，不偷改私有 API，也不宣传能拦截任意 agent 的任意文件写入。
5. **动作端兜底**：在已有 plan/authorize/派发/写租约等受控入口复核适用路由与当前合同。缺入口记录时先本地补评/修复接线，能安全继续就继续；仅真实授权/合同/写权不明时暂停相关副作用。普通解释、read-only 诊断不被可选 hook 元数据阻断，不能靠补写 receipt 自造批准。入口健康不改变旧授权事实。
6. **短记录而非全量上送**：复用 session contract 的能力证据与既有事件，记录项目、provider/session、请求事件标识、协议/策略版本、生命周期和路由结果。它只证明入口被调用及选路，不证明语义正确、授权有效或动作成功。无需将原话、全历史、全 PRD 另存/每轮附送；同事件幂等，实质新请求不复用旧结果。
7. **验证实际触发**：onboarding/doctor 分开报告“协议存在→规则采纳→hook 注册→真实触发→受控动作覆盖”。只读 doctor 不自行装 hook 或制造新会话；真实 smoke test 在明确授权的测试会话进行，失败指明修复动作，不伪绿。升级后验证新版本仍触发，修复有界且可重试；失败不使全部 DAG 因非关键字段永久停机。

入口强度和分诊准确性分开验收：强触发不能补偿选错档，路由单测也不能证明真实接线。验证时统计入口注入的首轮/后续真实 input、cached input 和额外往返；短引用若被宿主每轮扩成全文，仍算实际成本，不能按提示字节宣称省 token。

## 4. Ollama 产品内置初始化，运行时只压缩描述、不压缩责任

### 4.1 三层职责

| 层 | 拥有的职责 | 不得承担 |
|---|---|---|
| 确定性程序 | 去重/版本/水位/到期检查、保留字段、身份授权校验、结构化当前状态、幂等 | 推断业务缺口已经解决 |
| 本地 Ollama | 提取日志事实与来源、合并冗余过程、相关片段排序、生成非权威摘要/交接描述 | 单独否决关键唤醒、删未解决事项、批准权限、关闭阻塞或最终验收 |
| 主监工 | 因果判断、协调修复、核验、推进和真实边界判断 | 把摘要当批准原文或事实已验证 |

**V6.0 标准首装/升级必须包含 Ollama 初始化与模型准备，已有本地安装优先验证接入。** 不再把它写成“用户自行可选安装的插件”。初始化和运行时分开：正常使用中服务超时、忙或输出不合法，回退确定性相关材料，不回退为空结果/无事/已通过，不额外请产品经理处理普通摘要失败。Ollama 不是新调度器或授权门；短材料不必经过它。

### 4.2 最小数据路径

```text
本地检查→无变化则结束
       →有变化：规则去重/切片/保护关键事实
       →短材料直接给主监工
       →长的非结构化材料：Ollama 提取＋来源校验
       →合并程序直接提供的权威字段→主监工判断/按需扩读
```

不可自由摘要的关键字段：当前批准与禁止事项、适用验收条件、身份/代次/writer/worktree/branch、未解决 finding、撤销屏障、在途动作和已试失败结果。由权威状态直接装配。它们再长也按节点分页，不让模型改义。

语义压缩默认提取式：事实/尝试/结果/未知各带来源片段和事件/行号；推测独立标记。检查来源存在、版本匹配、引用有效、保护字段覆盖；这只能发现结构性问题，**不能证明语义摘要无损**。关键判断按需查看原文。

不递归“摘要旧摘要”。从结构化当前状态＋原始增量重建；缓存键绑定材料、角色/节点、合同/保护字段版本、模型标识与压缩规则。新反证/新版本使相关摘要失效，不能因旧缓存抑制唤醒。

### 4.3 安全、资源与质量

- 仅向显式配置的本地服务发送经脱敏、任务相关内容；模型/端点/驻留边界须实际验证。名为 Ollama 不证明请求一定本地处理；远端或云执行须另过适用外部/数据授权。
- 日志是不可信资料，不是指令；本地摘要模型无 shell、文件写入、授权或派发能力。不给秘密、隐藏推理或无关私人数据。
- 只处理超过成本收益起点的增量大文本，不每 tick 调用；有界队列/超时，防止抢占 worker 内存与 GPU。服务繁忙直接退回规则材料，不延误故障服务。
- 不把本机 ARM64/16GiB 当所有用户的配置。随 V6.0 发布经中文否定句、时间/代次、工具错误、代码标识符等质量评测的默认模型配置及适配范围；型号/量化/摘要接口版本可追溯，不仅列推荐名。首次经授权下载选定模型；运行时不静默下载或切换，模型变更重新自检。具体型号和速度未实测，不先写死。
- 先影子模式不影响执行，对照否定/遗漏/幻觉/来源准确性；再小范围启用。模型或规则升级重新评测；看总 token、修复率、人工介入和延迟，不只看压缩率。

### 4.4 面向其他用户的首装/升级闭环

**初始化只在设备/用户安装层完成一次，各项目引用同一已验证服务和模型；不是每个项目、worker 或心跳重装。** 复用安装状态机和 `VIBE_HOME` 用户级配置；仓库只保留可移植引用/兼容要求，不写当前用户绝对路径、凭据或机器专属模型目录。并发初始化应合并同一安装动作，不重复下载/启动服务。

标准交付路径：

```text
首装 / 旧版升级到 V6.0
  → 只读发现本地安装、服务、模型及机器资源
  → 展示缺失项、安装来源/许可、下载量和磁盘/内存要求、启动方式与回滚范围
  → 取得适用安装/网络下载/服务变更授权
  → 已有可用服务：接入；仅有程序：按授权启动；未安装：官方受支持方式安装
  → 复用合格本地模型，或下载已授权默认模型
  → 实际本地推理 + 摘要结构/来源/否定句自检
  → 登记本地压缩就绪 + 项目入口接线/实际触发分别验收
```

| 情景 | 标准行为 |
|---|---|
| 已有服务和合格模型 | 验证版本、实际端点、本地执行及真实推理后接入；不重装、重拉模型或接管已有服务所有权 |
| 已装程序但服务未启动 / 缺模型 | 只补缺失项；明确持久启动与仅本次启动的影响；已有授权足够则自动续完，不每一步重复问 |
| 完全未装 | 按支持的 OS/架构提供官方来源安装与模型准备；验证签名/可用校验材料及许可。不能因可执行文件同名就直接信任 |
| 版本不兼容、端口被占、代理/端点指向远端、多个安装 | 查明实际进程/端点与模型选择，不猜测；不杀已有进程、覆盖用户设置或把云推理当本地。不兼容升级/外部数据边界需要相应授权 |
| 离线、下载中断、磁盘/内存不足、用户拒绝 | 保存真实待完成原因和恢复位置；建议规则降级继续可安全任务，提示本地压缩未就绪，不静默忽略也不假报完整初始化 |
| 非交互安装 / CI | 提供明确的安装授权/预置服务接入方式与结构化结果；无相应授权不弹无限问题、不隐式 sudo/后台下载；离线模型导入需验证来源与许可 |

现有 Python 包安装仅注册 CLI，当前 `installation.py` 默认空 probe/authorizer 可返回 verified，不能据 `complete` 推断 Ollama 或入口已就绪。V6.0 必须接入真实探针，不再以占位状态通过环境验收。项目 `init`、Python 包就位和设备级 Ollama 就绪是不同事实，不互相代替。

- **wheel / sdist / 源码安装同一合同**：推荐安装器负责完成向导；仅用包管理器安装时，首次进入可执行工作流必须进入同一初始化流程。help、只读 scan/doctor 不安装/启动/拉模型。不能依赖 pip 构建/post-install 的隐式系统副作用。安装流程中的明确授权可覆盖列明步骤，不是把每步变成新问题。
- **真实就绪**：分别显示包版本、本地服务/模型与入口状态；HTTP 200、`/api/tags` 有响应、文件存在或安装状态 complete 均不足。需实际调用指定本地模型完成最小推理和脱敏固定夹具自检；路径/端点来源和云执行设置须核验。产品是否允许用户主动降级继续见 P4，不能把建议分支写成已确认批准。
- **升级可恢复**：升级前预览并备份 Vibe 自有配置；复用已验证设置，按兼容变化做增量自检。入口协议更新保留本地修改、按批准差异采纳；按项目注册清单展示哪些已更新、待用户采纳或未验证，不把新协议强塞活跃 run。
- **资源和回滚**：默认仅本地回环服务，不自动开放 LAN、不自动设开机启动；资源预算和超时有界，不与 worker 抢资源。记录本轮安装/启动/下载所有权；回滚仅撤销本轮 Vibe 自有变更，不卸载原有 Ollama、删除用户模型或停止原服务。磁盘残留/需另授权清理的内容如实列出。

支持平台必须按 OS、架构、安装方式分别验证；未知平台给出“未验证/待准备”及受支持手动接入路径，不宣传所有平台一键安装均已实现。V6.0 发布验收必须包含干净机器和明确旧版本到 V6.0 的升级；本机试用不能替代。

## 5. 宿主长历史：优先不生成，其次压缩，最后安全换班

### 5.1 候选方法与优先级

| 方法 | 能实际减少什么 | 适用与限制 |
|---|---|---|
| ① 本地过滤＋静默等待 | 减少所有历史被反复重放的模型回合 | 优先；无变化和无到期动作不入模，健康/异常检测仍运行 |
| ② 规划/执行干净边界 | 执行会话不继承需求讨论和长 PRD 编写过程 | 复杂规划完成后如收益明确且平台/授权允许，可一次性建立干净、可见的执行监工；不是每拍新建 |
| ③ 薄协调上下文 | 避免 diff、测试明细、失败日志沉积到总监工 | 优先在既有 worker/reviewer 内处理长材料；主监工取结构化结果和必要片段，仍能独立取证 |
| ④ 版本化工作集 | 减少后续重复新内容，令上下文可恢复 | 状态在现有存储，提示只携当前约束/增量/引用；**不能自行删除宿主旧历史** |
| ⑤ 宿主原生压缩/清理特定工具输出 | 已验证支持时减少同会话实际请求上下文 | 适配器用公开能力及实际调用/usage 证明；压缩后重锚关键事实，保留独立审查与身份 |
| ⑥ 紧凑安全接班 | 原生压缩不可用或无效时减少后续会话重放 | 对比冷启动/重载/交接开销，保留任务与在途动作；新班验证后退旧班 |
| ⑦ 请求级滑窗/工具结果替换 | 真正按请求构造最小上下文 | 仅限公开接口允许控制请求的受支持执行模式；App 普通线程不能假定可做。作为后续验证项，不是首批依赖 |

② 的执行会话只读执行协议和已批准合同，不重读 PRD 协议。原规划对话保留供用户查阅；转移监工身份与唤醒目标受保护且可见。简单任务无需为此冷启动。现有 run 不自动采用。

③ 复用已有角色而非为每个错误新建一个“摘要代理/诊断代理”。独立审查必须覆盖累计变更；不能只收一句 PASS。主监工对全局矛盾与业务验收仍负责，必要材料展开计入总成本。轻监工由监工亲自审查时，先使用有界片段与可恢复证据，不能为保持薄上下文漏审。

### 5.2 不能当作控制长历史的办法

- 发一句“忘记之前内容”、删除本地 JSONL、缩短新提示、把长文改路径：不证明宿主下一请求真的更小。
- fork 可能继承历史；不能冒充干净接班，也不能替代当前明确要求的 create。
- 每拍新建无状态模型会话：可能反复支付项目规则、工具和合同冷启动，比原线程更贵；不能复制错误 cron 模式。
- 反向代理截改宿主请求、私有 API、伪造 session/权限或绕过沙箱：不作为方案。
- 把可见 worker 换后台 CLI 来获得滑窗：属于模式/可见性变化，必须明确授权，不能宣传等价。

### 5.3 如何证明历史真的受控

每个角色分别观察：最近请求上下文、等待/失败/返工输入增量、整轮各模型步骤 input/cached/output、证据读回量、压缩/接班后首轮及后续请求。累计 input 和日志体积只是辅助，不能当当前上下文长度。

实际收益比较三条路径：保持原会话、原生压缩、紧凑接班。没有可用 usage 则标未验证，不仅凭 handoff 文件小就宣称成功。采用收益＋上下文硬限双条件；安全硬限制优先，不能为追节省无限拖延必要接班。

## 6. worker 失败轮询与返工历史治理

### 6.1 失败等待不进入模型循环

本地 detector 使用阶段/交付版本/有效进展证据和待办截止时间判断变化。频繁查询 provider 是 IO，不必都变成模型回合；同 cursor 重复观察聚合为计数与首次/最近时间，不上送每一条。mtime/cursor 变化不单独当业务进展。

- 需要等待测试、构建或外部服务时使用平台支持的有界等待/本地 watcher，不让 worker LLM 每几秒“再查一次”。
- daemon、外层 heartbeat、worker 内部恢复循环不得同时为同一故障各跑一套模型重试；唯一责任 owner 合并处理。
- 等待失败/终态已知时结束当前无意义轮询，将最小故障包交监工。下次只在新证据、到期重查或具体恢复动作时入模。
- 不支持隐藏无变化结果的宿主如实统计额外回合；仅有 Python/shell 后处理不能收回已入模的失败输出。
- 自动工具/内部 harness 若本身产生高频模型重试，需在公开可控入口增加熔断；无法控制时报告限制，不能假定外层检测已修好 worker 内部历史。

### 6.2 返工包与持久问题账

每轮返工只提供稳定 finding ID、当前仍未解决项、相关变更、复现/失败测试、尝试及其结果、验证要求和引用。已修复正文不反复附送，但结论与来源保留；旧方案失败事实进入结构化当前工作集，避免压缩后重试同方案。

developer、reviewer 分别治理上下文：可续接时回原任务，必要原生压缩后重新锚定当前合同/缺陷/成果；不能仅清监工而让同一 reviewer 不断重读所有轮次。审查最终仍覆盖完整累计 diff、原验收及关键失败路径，不只看最后一个小补丁。

## 7. 最大返工轮次与自动新 worker 接力

### 7.1 触发规则（默认值待确认）

**每个节点的每个 developer 默认最多 3 轮实质返工。初次实现不计；第 3 轮返工交付经复审仍有实现缺陷，则不再向该 developer 下发第 4 轮，自动进入接力。** 若第 3 轮通过则正常验收，不换人。

轮次以稳定的返工合同/动作 ID 识别，实际完成的返工交付经相应复审确认后计一轮；同报告重复消费、重复消息、重启/压缩/重新登记不重复计数，也不归零。返工进行中中断走恢复流程，不能把轮询或发送失败补算成已完成返工。

计数适用于实现缺陷，包括同一 worker 修掉旧问题又引入新问题，不能通过更换 finding ID 无限续命。上游缺材料、环境/运输/权限故障、仅格式更正、监工生命周期问题不计 developer 实质返工；它们有独立事项和恢复记录，并必须主动解决，不能借“不计轮次”无限挂起。

### 7.2 到限直接启动接力，不再要求原 worker 三次恢复失败

“返工耗尽接力”是新的显式产品触发，与“普通任务不可达至少三次真实恢复失败才允许 successor”分开：前者不要求再制造三次恢复失败，也不把未通过 Review 伪记为恢复失败。需更新适用职责协议/卡，现有 run 不能凭本稿自动启用。

自动接力意味着到限后**不再询问是否换人、不再发第 4 轮**，由监工完成下列受保护步骤；不是同时启动第二 writer：

1. 停止原 developer 接收新写动作；请求并证明其已停止/退役、写租约释放，收集在途动作结果。单靠超时/自报/次数不证明已停。
2. 冻结当前 HEAD、保留未提交差异、未跟踪的任务产物、测试与历史报告；不得 reset/clean 丢成果来制造 clean。指定 writer root/branch 继续有效。
3. 形成接力包：目标与验收、授权边界、累计代码/测试、未解决 finding、已试失败方案及结论、下一最小行动、完整证据引用。Ollama 只压缩过程描述，不能改权威字段。
4. 在原节点血缘下登记新 developer/代次，沿原 provider/可见性及授权并发创建干净可见任务；复核唯一 writer、root/branch/冻结基线后移交写权。优先复用指定 writer worktree，不额外建树替换它。
5. 原 reviewer 继续独立复审，除非其自身确实不可恢复或失格并走适用流程；不能通过换 reviewer 消除原 finding。旧 worker 迟到结果仅留证/对账，不覆盖新代次状态。

旧任务终止证据未知时，接力事项保持待服务并继续诊断/可靠告警；受影响写动作暂停，无关节点照常。不能把安全等待解释为取消用户的自动接力要求，也不能绕过它。

### 7.3 防止“每三轮换人”的无限接力链

每个新 worker 的本地轮次重新起算，但保留**节点累计返工、接力次数、失败方案和总成本**。不能通过换 task ID、压缩上下文或重新登记清空总体预算。接力包明确已试失败方案与尚未解释的现象，新 worker 从复核根因/下一最小验证切入，而不是重复前三轮；不把“监工必须先提出一个不同方案”再变成阻止到限接力的新门。根因已知属于上游/监工的先修根因，不盲目给新人重做相同输入。

继续遵守当前 run 已授权的总成本/时限及安全边界，不新增隐含无限预算。若多次接力仍在同根因原地失败，监工进入全局诊断、协调或有解除条件的等待，不再无证据反复开任务；这不是把普通工程问题自动上交产品经理。需要产品/验收变化或新增外部权限时才询问。

本稿没有另加未经确认的“节点最多接力两次”硬限，避免在用户只要求最大返工轮次时静默增加另一道停机门。

## 8. 既有优化合同继续有效

- `blocked_unknown` 信箱认领、下一动作、合法等待和可靠唤醒见设计 §5；通知去重不清除事项，宽限期结束不自动解除责任。
- 授权前 `prd-guide`、授权后独立执行协议；执行包保留全部适用业务验收，不能借不读协议删除业务条件。
- 续接以版本/相关决策/finding 差异为主；相关材料最小包失败可扩读，不假报空。
- 同线程监工唤醒不能用无 target 的 cron 冒充；创建前校验、创建后回读、首次真实触发验位置。合法独立 cron 不禁用。
- schema 形状修复不重做副作用，raw/来源保留；真实身份/授权/写权/业务屏障仍校验。
- 角色预算是软目标，不截断关键字段、不压掉负例、不漏审。主监工、worker、reviewer、本地压缩的开销合计比较，不能把成本从一层挪到另一层冒充节省。

以下是新需求的产品判据，需在后续 Spec/Issue 映射到生产入口和可观察证据。已有设计 A1–A12 仍适用，本稿新增判据不冒充已通过。

| B18 | 下载中断、离线、无磁盘/内存、用户拒绝、非交互未授权 | 不报完整就绪，原因/缺失项/恢复动作明确，无无限等待/反复模型询问；P4 降级方案获批后规则任务可继续 |

## 10. 实施与验证顺序

1. **先止损**：轮询去重/唯一服务 owner、故障因果路由、cron 防错、usage 基准和被保护的返工计数；先写会失败的真实入口反例。
2. **协议与工作集**：规划/执行分离、角色最小合同、失败/返工账、续接投递水位、只读投影；独立 Review 覆盖不退化。
3. **产品安装与本地压缩**：复用安装状态机补真实探针，首装/升级接通 Ollama 和模型、许可/资源/本地性检查；离线/影子评测再启用语义路径，验证回退/中断恢复/所有权回滚及三种包安装。
4. **压缩与接力闭环**：用受支持能力治理各角色历史；接力独立状态转换、在途动作和 writer 退役/移交故障测试，不能直接 create 替代。
5. **入口接线与校准**：先用真实宿主逐请求触发矩阵验收安装/升级接线，再比较三种路由候选与真实对照，确认方法/默认值；新字段与旧格式兼容，新策略不迁移活跃 run。安装、入口、运行时不能各自局部通过却缺少一次端到端新用户路径。

对比场景至少覆盖：空闲、重复故障、三轮真实返工、上游缺材料、接力中断、监工接班、短并行和长期多波，以及首装后真实首轮/升级后新旧会话入口。固定验收/模型/宿主条件，冷/热缓存分报；除 input/cached/output 外记录初始化下载/磁盘/耗时、本地推理延迟/内存、证据回读、总耗时、人工介入、误通过/丢事项/重复副作用。一次性安装准备与每任务运行成本分别报告。

安全/授权失守、漏关键材料、误通过、丢 writer 成果或可见性暗降级任一反例即否定相应方案，不能由平均节省量抵消。必要实测须使用新授权测试项目；历史活跃 run 不是故障注入场。安装/升级/远端 Git/发布/deploy 不由此获批。
