# AGENTS.md 补丁建议（2026-10-28，5.2.0 整合）

状态：建议，待产品经理确认后由人工合入；本文件不直接修改 `AGENTS.md`。

背景：5.2.0 把监工改成「`vibe daemon` 守护程序 + 按需短会话 + 三级自愈」，Claude Code 默认后台派发，发布时不再询问工程参数。`AGENTS.md` 里仍有按旧形态写的规则，且 §6 与 `prd-guide` 有大段重复。以下三处建议修改。每处都给出现状、建议文字和理由。

## 1. Claude Code 默认后台派发，可改选可见

现状（§6）：「显式独立任务」是首选合同，Claude Code 等桌面 App 优先通过原生任务能力创建用户可见任务；降级为 background subagent 必须披露。

建议在该段末尾追加：

> Claude Code 在配置了后台启动器、且会话用 `vibe attest` 登记了 `claude-code.background_task.launch` 后，授权卡默认走后台派发（`claude-code-background`），授权一次、不用盯屏幕；授权卡上可改选可见卡片。后台派发属于「已知降级」：能力报告、授权卡和交付必须披露不可见、只能在真实终端 `claude attach` 进入、返工续接受限三项限制，不得标成完整可见自动化。可见卡片模式下每个节点仍需用户点一下确认。

理由：产品已把后台作为 Claude Code 的默认，AGENTS.md 里「完整可见自动化」的表述需要同时写明这个默认和它的披露义务，避免监工把默认后台误当成违规降级而反复询问。

## 2. 监工新形态：守护程序 + 短会话 + 三级自愈

现状（§6「监工规则」与 §9）：只描述监工会话、心跳和换班；没有守护程序，也没有自愈分级。

建议在「监工规则」列表后新增：

> 监工形态：授权后启动 `vibe daemon`（分离的本地进程，持监工租约），确定性地 resume、收交付、派后台 worker、拉 reviewer、接受节点和一级自动重试，不调用模型；产品经理会话只保留 60 分钟兜底检查（先看 `vibe daemon status`，失活则重启或上报）。节点空转时三级处理：一级自动重试；二级拉起一次修复短会话，输入排查包、监工卡和授权范围，必须以 `vibe heal-verify` 结束并由守护程序复核，每个运行同时最多一个短会话且有次数与 token 预算；三级（同一空转指纹两次修复无进展，或需要越过产品范围、授权卡、deploy、凭据与系统权限边界）建决策卡并推送到登记的产品经理会话。守护程序崩溃或租约丢失不得产生第二个写入者；短会话命令不可用或超时记为 `unknown` 并升级，不得当成功。
>
> 发布时不向产品经理询问心跳间隔、换班上限、模型或拓扑等工程参数，由 vibe 按平台推导；节点的能力档位（`light` / `standard` / `deep`）由 vibe 派生，派发时按平台换算模型，具体模型名不进授权指纹。Claude Code 没有换班原语，永不换班。

同时在 §9 的 `tasks.json` 条目后补充：守护程序的 pid、心跳、最近错误和短会话次数写入 `.vibe/runs/<run-id>/`，不得含凭据。

理由：把已经写进协议和代码的新形态补进项目规则，监工与 worker 读到的规则才与实际行为一致；「不问工程问题」与 §2 的「只在会改变结果时提问」一致，但需要点明心跳与换班上限这两个原先要问的参数。

## 3. 精简与协议重复的运行手册

现状：§6 里的换班、心跳、自愈、合并等规则与 `vibe_guide/protocols/prd-guide.md`、`supervisor-card.md` 各写一份，改一处要同步三处。

建议：

- §6 保留**边界与授权**（一次授权范围、deploy 单独授权、唯一 writer、worktree 约定、一致性纠偏的取证顺序、自动扩范围的两类判据）；
- 删除或改成指针的内容：心跳间隔与换班阈值数字、`rotate` 接班步骤、心跳指令全文、信箱回写格式、平台工具名对照——统一写「以 `prd-guide` §6 与随包监工卡为准」；
- 合并规则按新行为表述：授权卡允许远端 Git 动作时，独立终审通过、P0–P2 清零后由 vibe 标记「可合并」，监工执行合并命令，vibe 核实合并提交可达目标分支后才记为已合并；该授权不含 deploy、凭据和系统权限。
- 引擎证明有效期写 72 小时，超期由同一 plan revision 的重新授权自动续签，不要求重新发布计划。

理由：单一事实源。运行手册只在协议文件里维护，AGENTS.md 只留不会随实现变化的边界，降低文档与代码再次分叉的概率。

## 不在本建议内

- 不修改 `AGENTS.md` 里的 deploy、凭据、系统权限和授权边界条款；
- 不改 `acceptance_scope_rule_approved` 与 §6 判据二成对出现的约束；
- 版本发布和本机升级是独立动作，另行授权。
