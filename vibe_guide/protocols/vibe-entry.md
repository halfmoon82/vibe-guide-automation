# Vibe Guide · 新会话入口协议（宿主 agent 用）

> 本文件随 vibe 包发布，由 `vibe init --confirm` 物化到 `.vibe/proposals/skills/vibe-entry/SKILL.md`；物化后 vibe 永不改写它，你的本地修改在重复 init 后存活。
> 面向 Claude Code / Codex 等宿主 agent。**完全自包含**：只装 vibe 即可完整执行本协议，不依赖任何外部技能。

## 0. 分工与适用边界

- 本协议只做一件事：**新会话收到请求后的入口自评与路由**——会话内完成 S0/S1 判断，只有确认为复杂的请求才调用 vibe CLI。
- 被判为复杂之后的路径（PRD 引导、节点拆分、授权卡、监工）按 `.vibe/proposals/skills/prd-guide/SKILL.md` 执行；本协议不重复其内容。
- 宿主已装 `complex-task-methodology` 技能时，可（可选）用其完整评分表替代 §2 的速查表；未装不影响本协议任何一步。
- 纯问答、翻译、解释、单次查找、继续/确认类请求不启用本协议，直接回答。「排查」类请求含只读的日志/生产数据分析与诊断定位，不在此白名单内。

## 1. S0 白名单（零成本，直接执行）

命中以下任一类型 → 直接做，不评分、不调 vibe：

| 类型 | 例子 |
|---|---|
| 简单问答 | 「什么是 X」「解释这段代码」「翻译这句话」 |
| 继续/确认 | 「继续」「好的」「然后呢」 |
| 单次查找 | 「帮我搜 X」「读一下这个文件」 |

有实现意图、跨文件、或路径不明 → 进 §2 评分。

## 2. S1 五维评分（会话内完成）

五维以 vibe planner 的 `TaskContext` 为唯一真相源，字段名与顺序固定为 `steps`、`domains`、`uncertainty`、`failure_cost`、`toolchain`：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| `steps` 步骤数 | 1-2 步 | 3-5 步 | 6 步以上 |
| `domains` 知识域 | 单一文件/模块 | 跨模块 | 跨系统/架构级 |
| `uncertainty` 不确定性 | 路径明确 | 部分需调研 | 大量未知 |
| `failure_cost` 失败代价 | 可随时回退 | 中等影响 | 不可逆/影响生产 |
| `toolchain` 工具链复杂度 | 现有工具即可 | 需新装/新配 | 多工具编排 |

阈值（与 vibe planner 路由一致）：

- **<=8**：直接执行，不触碰 vibe。
- **9-15**：轻规划（列出步骤要点），不触碰 vibe。
- **>15**：进 §3 的 vibe 正式路由。

凡经过本节评分的请求，评分后必须先输出一行可验证的 S1 结果再行动，形如 `S1：11→轻规划（不触碰 vibe）`（<=8 为 `S1：8→直接执行（不触碰 vibe）`；>15 为 `S1：17→vibe 正式路由`；拿不准时给区间估计并标注「拿不准」，按 >15 处理）。宿主自有强制状态行/卡片协议时，把该行并入该状态行作为 `S1：` 字段，不另起一行。

防呆与动态升级：

- **拿不准一律按 >15 处理**进 §3——误进复杂无害，误放简单危险。
- 执行中出现以下任一情况，停下来重新评分并升级档位：同一方案连续失败 2 次以上；实际步骤数超过预估 2 倍；发现意外的阻塞依赖；发现影响共享/生产系统。

## 3. 复杂路径（>15 或拿不准）

```bash
vibe scan --json                                        # 只读：确认项目态与会话门
vibe plan --request "<用户原话>" --s1 s,d,u,f,t --json    # 正式路由；s,d,u,f,t 为 §2 五维分数
```

- `--s1` 五个数字的顺序即 `steps,domains,uncertainty,failure_cost,toolchain`，各取 0-5 整数。
- `route` 为 `simple`/`light_plan`：按 vibe 的路由结果直接执行（vibe 的正式路由优先于你的自评）。
- `route` 为 `complex`：记下 `plan_id`，按 prd-guide 协议进入 PRD/Spec/DAG/授权卡流程。
- **会话门阻塞（`session_gate_blocked`）时必须停下报告**，不得伪造状态、不得跳过门禁、不得手写 plan 工程字段。
- scan 报告未知/超时保持 `unknown`，不得当成成功或永久不可用。

## 4. 授权纪律（与评分无关，始终生效）

- commit / push / 创建 PR / merge 属 Git 远端动作授权组；deploy、发布、生产写入、凭据永远单独授权。
- 测试通过、PASS、文件存在都不是业务批准、发布或 merge 事实。

## 5. 短提示

项目已初始化且 Spec/计划/状态存在时，可使用短提示：「扫描适配」「初始化项目」「继续规划」「启动监工」「继续监工」。短提示不绕过需求决策、DAG 确认、授权与门禁。

## 6. 不做什么

- 不绕过任何门禁与授权边界；不替用户做产品决策；不把自评分数当 vibe 的正式路由结果；不为简单任务调用 vibe（那是本协议存在的意义）。
